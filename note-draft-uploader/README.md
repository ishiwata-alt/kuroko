# note下書き自動投入ツール

ローカルの「note貼り付け用HTML」を、**note.com に「下書き」として自動で入れる**ツールです。

## このツールの約束（安全設計）

- 対象は **あなた自身がログインしたnoteアカウントだけ**
- **「下書き保存」までで止めます。公開は絶対にしません**
  （`公開に進む`・`公開設定`・`有料` などのボタンは、コード側で**クリック禁止**にしています）
- 有料ライン等の設定は**一切しません**。本文の下書きだけ
- ログインは **あなたが一度ブラウザでログインしたセッションを再利用**します。
  **パスワードやCookieはコードに書きません**。ログイン状態は `.note-user-data/`
  というフォルダに保存され、`.gitignore` でGit対象から外してあります

---

## 0. 前提

- **Mac** で作業します（このツールはあなたのMac上で動かします）
- 対象HTMLの場所（初期設定）: `~/Documents/note記事/note_html`
  - 違う場所なら `config.mjs` の `inputDir` を直すか、実行時に
    `NOTE_HTML_DIR=...` を付けてください
- Node.js（v18以上）が必要です。入っていなければ [nodejs.org](https://nodejs.org/) からLTS版を入れてください
  - 確認: ターミナルで `node --version`

---

## 1. 最初の準備（1回だけ）

ターミナルを開き、このフォルダに移動して、必要なものを入れます。

```bash
cd <このリポジトリを置いた場所>/kuroko/note-draft-uploader

# 必要なパッケージを入れる
npm install

# Playwright用のブラウザ本体を入れる（初回だけ／少し時間がかかります）
npx playwright install chromium
```

### あなたが最初にやること = 一度だけログイン

```bash
npm run login
```

- ブラウザが開きます → **いつも通り note にログイン**してください
- ログインできたら、**ターミナルに戻って Enter** を押す
- 「✅ ログイン状態を確認できました」と出れば準備OK
  （この状態が `.note-user-data/` に保存され、次回から再利用されます）

---

## 2. まず「中身の確認」→「1本だけ下書き」

### 2-1. 投稿せずに、抽出結果だけ確認（安全・おすすめ）

```bash
npm run dry-run
```

- noteには**一切触れません**。各HTMLから取り出した
  **タイトル**と**本文の先頭**を `logs/dry-.../` に書き出すだけです
- ターミナルに「タイトル: 「〇〇」← どこから取ったか」が出ます
- **タイトルが違うと感じたら** → 下の「タイトルの直し方」へ

### 2-2. 1本だけ、実際に下書きを作る

```bash
npm run one
```

- 先頭の1本だけ、noteに**下書きとして**作成します（ブラウザが開いて自動で動きます）
- 終わったら、**note の下書き一覧**を自分の目で確認してください
  👉 https://note.com/notes （「下書き」タブ）
- タイトル・見出し・太字・リスト・コードの見た目が意図通りか確認

**ここでOKが出てから、次の一括処理に進みます。**

---

## 3. 残りをまとめて処理

確認できたら、全部を一括で下書き化します。

```bash
npm run all
```

- 全HTMLを順番に下書き作成します
- **1本失敗しても止まりません**。失敗した記事は**スキップして次へ**進み、
  `logs/run-*.jsonl` に理由が記録されます
- 各記事のスクリーンショットが `logs/shots-*/` に残るので、後から確認できます

### 便利な指定

```bash
node run.mjs --all --limit 3        # 先頭3本だけ
node run.mjs --file きじ.html        # 特定の1ファイルだけ
```

## タイトルの直し方（案内ボックスの指定）

タイトルは、既定では**自動推測**します（案内ボックスらしき箱 → 最初の見出し →
`<title>` → ファイル名、の順）。

もし違うものが選ばれるときは、実際のHTMLを開いて、タイトルが入っている
「案内ボックス」の目印（CSSセレクタ）を `config.mjs` の `titleSelector` に設定します。

```js
// config.mjs
titleSelector: ".notice-box strong",   // 例：class="notice-box" の中の <strong>
// titleSelector: "#guide h2",          // 例：id="guide" の中の <h2>
```

設定したら、もう一度 `npm run dry-run` で狙い通りか確認してください。

本文の範囲を絞りたいときは `contentSelector`（例 `"#article"`）を設定します。
未設定なら `<body>` 全体を本文にします。

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| `ログインが確認できません` | `npm run login` をやり直す |
| タイトルがおかしい | 上の「タイトルの直し方」で `titleSelector` を設定 |
| 本文の装飾が崩れる | `logs/shots-*/` のスクショを確認。note側で対応していない装飾は自動で簡略化されます |
| エディタが見つからない | noteの画面変更の可能性。`config.mjs` の `note.titleSelectors` / `note.bodySelectors` を調整 |
| 途中で失敗 | 止まらずスキップします。`logs/run-*.jsonl` で失敗した記事と理由を確認 |

## 仕組み（技術メモ）

- **方式(A)**：ログイン済みブラウザ（Playwright persistent context）で
  実際のnoteエディタを操作します
- 本文は **HTMLごとエディタに「貼り付け」** し、note側に装飾（見出し・太字・
  リスト・コード等）へ変換させます。これが見た目を保つのに一番確実です
- 保存は **noteの自動保存（下書き）** に任せ、公開系の操作は行いません
- ログイン情報はコードに持たず、ブラウザプロファイル（`.note-user-data/`）として
  ローカルに保存・再利用します
